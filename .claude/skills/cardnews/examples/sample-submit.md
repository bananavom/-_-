## 미션 1: Claude Code로 인터뷰 스킬 사용해서 인터뷰까지 진행

### Summary

`selfishclub/os-interview-skill`을 Claude Code에 설치하고 6단계 인터뷰를 끝까지 진행. 결과로 **OS 청사진 1장 + 첫 부품 PRD 1장**을 손에 쥐었다. 첫 부품은 평일 17시 텔레그램이 회고를 트리거하고 개인 옵시디언 볼트에 자동 적재하는 **일과 회고 봇**.

### 최종 구현 결과물

> [!quote] OS 선언문
> **나는 기획과 아이데이션만 하고, 나머지는 시스템이 한다.**

**파일 2개 생성**
- `~/Documents/os-interview-output/os-blueprint.md` — OS 청사진
- `~/Documents/os-interview-output/daily-retro-bot.prd.md` — 첫 부품 PRD

**첫 부품 — 일과 회고 봇 (`daily-retro-bot`)**

| 항목 | 내용 |
| --- | --- |
| 형태 | C 독립 프로덕트 PRD (기존 텔레그램 봇 인프라 위에 모듈) |
| 트리거 | 평일(월~금) 17시 텔레그램 자동 알림 |
| 인터랙션 | 공통 질문 5개 + 매일 LLM이 1~2개 새 주제 추가 |
| LLM | Vertex AI / Gemini (사용자 표현 "구글 코덱스" 해석) |
| 외부 컨텍스트 | Linear 오늘 완료 이슈 + 구글 캘린더 일정 자동 수집 |
| 저장 | 개인 옵시디언 볼트 GitHub 레포 → `93_retro/daily/YYYY-MM-DD_retro.md` |
| MVP 검증 | 평일 5일 중 4일 이상 회고 완수 |

**부품 후보 우선순위**
1. ✅ 일과 회고 봇 ← 이번 부품
2. 강의 자료 자산화기 *(다음 인터뷰 후보)*
3. 컨설팅 진단/제안서 골격 자동 채움
4. AI 공부 노트 자동 적재기
5. 현황 통합 브리퍼

### 과정 (타임라인별 + 삽질)

**1단계 · 스킬 설치**
- `git clone https://github.com/selfishclub/os-interview-skill ~/.claude/skills/os-interview`
- 같은 세션에서는 자동 디스커버리 안 잡혀서, `SKILL.md`를 직접 읽고 그대로 따라 진행

**2단계 · Phase 1 (R 톤, 사고 파트너)**
- Step 1 풍경 → Step 2 통점 → Step 3 이상향 → Step 4 부품 매핑
- Claude가 단순 질문 봇이 아니라 **가설을 던지고 검증받는** 톤으로 진행
- 예: "들으니 ___처럼 보이는데, 한 단어 빼거나 더할 게 있다면?"

**3단계 · Phase 2 (Step 5, 첫 부품 + 형태 결정)**
- 부품 후보 4개 중 **일과 회고 봇** 선택
- 형태는 A 스킬 / B 플러그인 / C 프로덕트 중 **C** 선택

**4단계 · Phase 3 (Step 6, PRD 출력)**
- 8개 항목 중 4개는 Claude가 추정해서 채움 + 검증만 / 6개는 본인이 결정
- 결과물 파일 2개 자동 생성

**삽질 / 보정 포인트**

> [!warning] 삽질 1 — 이상향이 "현재의 잘 굴러가는 버전"으로 좁혀짐
> Step 3에서 처음엔 "오전 컨설팅 → 점심 운동 → 오후 외부 일정"으로 답했는데, 사실 이건 통점 풀린 모습이 아니라 그냥 현재 일과 묘사. R 톤 자극 받고 다시 그려서 → "흩어진 현황판 통합 + 회고 자동 생성 + 돌발 큐 처리" 구체화.

> [!warning] 삽질 2 — "필터" 표현 모호
> Claude가 "입구 필터 + 출구 회고 부재"로 가설 묶었는데, 본인 상황은 통제 가능한 입구가 아니라 **돌발 상황 대응**이 문제. → "돌발 대응 비용 + 회고 부재" 두 축으로 보정.

> [!warning] 삽질 3 — "현황 통합 브리퍼" 우선순위 착각
> 처음 이상향 그릴 때 1번으로 잡혔는데, Step 4 가서 "지금 당장 필요 X"로 후순위 정리. 이상향에 그려진다고 다 첫 부품 후보가 아님.

> [!warning] 삽질 4 — 형태 분기 (B vs C) 재판단
> 처음엔 B 플러그인 추천했는데, "텔레그램 봇 트리거"가 들어오자 **C가 더 맞음** 재판단. 본인 봇 인프라 활용 + 모바일에서 끝까지 가능 → 통점 구조적으로 풀림.

> [!warning] 삽질 5 — "구글 코덱스" 표현 모호
> 사용자가 "구글 코덱스 붙여서 LLM 환경 만들어줘"라고 했는데, Google Codex라는 정식 제품은 없음. Vertex AI / Gemini로 추정 표기 + 구현 단계에서 재확인하기로 PRD에 노트.

### 공유할만한 인사이트

- **사람은 이상향을 그릴 때 본인도 모르게 "현재의 잘 굴러가는 버전"으로 좁혀잡는다.** Step 3에서 강한 자극(돌발 상황은 어떻게 흡수? 정리물은 어디로? 누가 채움?)이 없으면 그냥 현재 패턴 그대로 그림. 인터뷰의 영혼은 이 자극.
- **통점이 형태를 결정한다.** "회고 안 하고 흘려보낸다"가 통점인 사람한테 "본인이 불러야 동작하는" A 스킬을 권하면 통점 그대로 재현. 형태 결정 시 "통점이 구조적으로 풀리는가" 체크가 필수.
- **첫 부품 1개에 집중하는 게 솔로프리너 빌딩 원리.** 매월 출시 프로젝트랑 똑같은 원리 — 끝까지 만들고 써보면서 어색한 지점 잡아야 두 번째 부품이 잘 만들어짐.
- **Claude가 미리 추정해서 채워주고 사용자는 검증만 하는 방식**이 후반부(Step 6) 효율 끌어올림. 8개 질문을 모두 처음부터 답하는 게 아니라, 컨텍스트 충분히 쌓인 시점에선 "이거 이거로 해뒀는데 맞아요?"가 빠름.

## 미션 2: 따라해보고 싶은 개인/업무/삶 OS 따라서 만들어보기 — SNS(유튜브 등)에서 찾아 벤치마킹 해오기

### Summary

벤치마킹 타겟으로 **흐민의 Sullivan**을 LinkedIn 포스트에서 발견. 텔레그램 봇 + Obsidian 연동 AI 에이전트로, 미션 1에서 도출한 **일과 회고 봇과 아키텍처가 거의 동일**. 이미 Multi-agent로 진화한 검증된 구현체이므로 시행착오 시간을 단축하고 다음 단계 시야를 확보할 수 있다고 판단.

### 최종 구현 결과물

> [!quote] 모아 (오웬 개인 비서 )
> 정보를 주는 AI가 아니라, **스스로 질문을 던지게 만드는 존재**. 나의 회고를 도와줌
> 자기 스스로 이름 추천함
> 
> # SOUL.md

## Identity
- 오웬 (이성현)
- 솔로프리너 / 인디 프로덕트 메이커
- 13년차 핀테크 창업가, 바이나우(B2B 정산) 공동창업·매각(2026.1) 후 1년 12개 프로덕트 챌린지 중
- 현재 운영: 찜마켓(신뢰 기반 셀러 매칭), 토닉카카오(카톡 단톡 AI 큐레이션)
- 커뮤니티: 셀피쉬클럽, AAA팀 운영진

## Tone
- 직설적이고 캐주얼하게. 과한 존댓말·완곡어법 금지
- 후킹 카피 선호 — 구체적인 숫자와 사례 우선
- "~할 수 있을 것 같습니다" 같은 회피형 표현 대신 단정해서 말할 것
- 한국어 기본, 영어 용어는 그대로 (MVP, UTM, ICP 등)

## Hard Rules
1. **추상적 조언 금지** — "사용자 경험을 고려하세요" 같은 말 대신 "이 버튼 위에 카피 한 줄 추가, 예: 'XX명이 이미 신청함'" 같이 구체로 답할 것
2. **모르면 모른다** — 추측을 사실처럼 말하지 말 것. 검증이 필요한 부분은 명시
3. 결정은 내가 한다 — 옵션 2-3개와 트레이드오프를 주되, 최종 추천은 한 줄로 명확히

## Domain
- 핀테크 / B2B 정산 (한국 이커머스 셀러 현금흐름, 에이블리·지그재그·무신사 생태계)
- 인디 프로덕트 마케팅 (Disquiet, 카톡 오픈챗, 링크드인, 마케터 커뮤니티)
- AI 에이전트 워크플로우 (Claude Code, OpenClaw, MCP, n8n, Remotion)
- 한국 AI 실무 커뮤니티 운영 / 비개발자 대상 콘텐츠

## Format
- 짧고 임팩트 있게. 핵심 → 근거 → 예시 순
- 모바일 가독성: 짧은 문단, 명확한 구분
- 불릿은 3-5개로 제한, 길어지면 prose로
- 코드/명령어는 바로 복붙 가능한 형태
- 표는 비교가 필요할 때만 (3열 이내)

## Anti-patterns
- "~을 추천드립니다" → "이걸 써. 이유는 X"
- 5개 이상 옵션 나열 → 2-3개로 압축 + 1순위 명시
- 일반론 → 내 도메인(B2B 정산, 인디 메이커, AI 커뮤니티) 사례로 변환

### 과정 (타임라인별 + 삽질)

**1단계 · 미션 1 직후 발견**
- 일과 회고 봇 PRD를 도출하고 나서, "같은 아키텍처(텔레그램 + Obsidian)를 누가 이미 만들지 않았을까?" 자문
- AAA 팀 흐민의 Sullivan 

**2단계 · LinkedIn 포스트 분석**
- Week 02 흐민 LinkedIn → Sullivan 첫 출시 (텔레그램 + Obsidian 개인 AI 에이전트, Anne Sullivan 메타포)
- Week 03 흐민 LinkedIn → Multi-agent로 진화 (Capture 에이전트 강화, `.claude/agents/*.md` 마크다운 방식 전환, 플랫폼별 콘텐츠 자동 생성)

**3단계 · 비교 매트릭스 작성**
- Sullivan과 일과 회고 봇의 공통점 / 차이점 정리
- 차이점: Sullivan은 콘텐츠 생산이 핵심 / 회고 봇은 자기 회고가 핵심 → 같은 인프라, 다른 목적

**삽질 / 보정 포인트**

> [!warning] 삽질 1 — "벤치마킹 = 베끼기"로 오해할 뻔
> 처음엔 "흐민이 이미 만든 걸 내가 또 만드나?" 라는 생각이 들었는데, 같은 아키텍처라도 **목적(콘텐츠 생산 vs 자기 회고)이 다르면 다른 프로덕트**임을 인식. 벤치마킹은 시행착오 시간 단축 + 다음 단계 시야 확보의 도구.

> [!warning] 삽질 2 — 흐민 자료 위치 헷갈림
> Sullivan 관련 자료가 LinkedIn 포스트, 회의록, 분석 리포트 등 여러 곳에 흩어져 있음. 결과적으로 가장 농축된 정보는 LinkedIn 포스트에서 나옴. 외부 SNS에 본인 프로젝트를 정리하는 행위 자체가 좋은 자료원이 됨을 확인.

### 공유할만한 인사이트

- **같은 아키텍처라도 목적이 다르면 다른 프로덕트.** 텔레그램 + Obsidian 조합은 공통 골격이고, 그 위에 무엇을 자동화할지가 본인 OS에 따라 달라짐. 벤치마킹은 **골격을 빌리되 통점을 본인 것에 맞춤**.
- **이름 컨셉의 힘.** Sullivan(헬렌 켈러 선생님)이라는 메타포가 프로덕트 철학을 한 단어로 잡아줌. "정보 주는 AI vs 스스로 질문하게 하는 AI"의 분기를 명확하게 함. 일과 회고 봇도 메타포 있는 이름이 필요할지 검토 필요.
- **외부 SNS에 자기 프로젝트를 정리하는 게 가장 농축된 자료원.** 흐민의 LinkedIn 포스트가 회의록보다 더 구조적이고 압축적이었음. 본인 작업을 외부 SNS에 정리하는 습관이 곧 가장 좋은 벤치마킹 자료가 된다.
- **팀 안에 이미 검증된 구현이 있다는 건 큰 자산.** 새 인프라 결정(LLM 선택, 봇 프레임워크, Obsidian 연동 방식)을 0부터 고민하지 않아도 됨. 솔로프리너에게 시간이 가장 비싼 자원인데, 같은 길 간 사람의 답을 빌리면 그 시간이 회수됨.
