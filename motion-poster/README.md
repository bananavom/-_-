# 스폰지클럽 3기 오프라인 모임 · 모션 포스터

정지 포스터 1장을 **67초 세로형(1080×1920) MP4 모션 포스터**로 만든다.
원본의 레이아웃·텍스트 위치·사진 구성·인물 얼굴·찢어진 종이와 테이프 질감을 그대로 두고,
각 요소를 레이어로 분해해 움직임만 얹는다.

```
./run.sh                      # assets/poster.png → out/sponge-club-3rd-offline.mp4
./run.sh path/to/poster.png   # 다른 원본으로
./run.sh --preview            # 스틸 컨택트 시트만 (타이밍 확인)
```

---

## 어떻게 원본을 그대로 유지하는가

정지 이미지를 움직이려면 글자를 사진에서 떼어내야 하는데, 떼어낸 자리에는 구멍이 남는다.
이 파이프라인은 세 단계로 그 문제를 푼다.

1. **키잉** — 글자·낙서·별·하트를 색상으로 오려낸다. 스프라이트의 알파는 획뿐 아니라
   **드롭섀도까지 덮는 부드러운 덩어리**로 잡는다. 그림자를 두고 획만 떼면 판에는 어두운
   유령이 남고 글자는 그림자를 잃어, 정지 상태에서도 원본과 어긋나기 때문이다.
   이웃 글자의 획은 서로의 덩어리에서 빼내, 타이틀이 올라올 때 옆 글자를 끌고 가지 않게 한다.
2. **인페인팅** — 오려낸 자리를 피라미드 push-pull 로 주변 색에 맞춰 메워 `plate.png` 를 만든다.
   파내는 영역과 스프라이트가 덮는 영역이 정확히 같으므로, 스프라이트를 제자리에 얹으면
   원본이 그대로 복원된다.
3. **타일** — `plate` 를 사진 영역별로 페더 크롭해 조각낸다. 타일은 `plate` 바로 위에 같은
   자리로 놓이므로 정지 상태에서 이음매가 보이지 않는다.

**검증된 결과** (대역 포스터 기준):

| 항목 | 결과 |
|---|---|
| 정지 상태 합성 vs 원본 | 평균 오차 **0.76/255**, 오차>16 인 픽셀 **0.03%** (잔차는 의도적으로 넣은 그레인) |
| 첫 프레임 vs 마지막 프레임 (루프 이음새) | **완전 일치** (최대 오차 0) |
| 정지 타일 숨김 최적화 | **완전 일치** (최대 오차 0) |

## 67초 타임라인

| 시간 | 내용 |
|---|---|
| 0.6 – 3.7s | 주변 사진이 **그룹 단위로 0.13초 간격**, 그룹 사이 0.28초 간격으로 등장. 살짝 크게·기울어진 상태에서 제자리로 내려앉아 스크랩북에 한 장씩 붙이는 느낌 |
| 4.3 – 5.3s | **스폰지클럽 3기** — 아래에서 46px 부드럽게 상승 (ease-out-quint) |
| 5.3 – 6.1s | **오프라인 모임** — 95% → 103% → 100% 짧은 POP |
| 6.1 – 7.0s | **노란 밑줄** — 왼쪽에서 오른쪽으로 손으로 그은 듯 드로잉 |
| 7.2 – 8.3s | **온라인에서 함께한 우리, / 드디어 만나요.** — 한 박자 늦게 페이드인 |
| 8.4 – 9.3s | **드디어를 감싼 원** — 각도 스윕 마스크로 손그림 드로잉 (374° 오버슛으로 겹쳐 그림) |
| 9.1 – 10.0s | **날짜** — 좌→우 마스크 리빌 + 테이프가 살짝 내려앉음 |
| 4.9 / 5.6s | **별** — 딱 한 번만 반짝 (이후 정지) |
| 6.3 / 8.5s | **하트** — 작은 팝, 이후 9~11.5초 주기로 미세 바운스 |
| 6.6 – 9.0s | **Better Together / Good Vibes / Sponge Club** — 손글씨처럼 좌→우로 번지며 등장 |
| 13.5 – 59s | **살아 있는 스크랩북** — 중심 사진 3장에만 100%→103~105% 느린 Ken Burns (주기 30·38·44초, 위상 다름), 보드 전체 0.6% 숨쉬기, 낙서 2개만 은은한 흔들림, 아주 옅은 빛이 종이 위를 천천히 지나감 |
| 63.9 – 66.9s | 등장 역순으로 그룹 단위 소멸 |
| 67.0s | 첫 프레임과 **픽셀 단위로 동일** → 이음매 없는 루프 |

모든 앰비언트 움직임은 `A(t)` 엔벨로프(13.5초에 0→1, 59초에 1→0)를 곱하므로
시작과 끝에서 정확히 정지 상태로 수렴한다. 이것이 루프가 정확히 맞아떨어지는 이유다.

## 구조

```
spec/layout.json      사진/글자 영역 좌표(정규화)·모션 종류·타임라인. 튜닝은 여기서만.
src/extract_layers.py 원본 1장 → plate + 타일 + 스프라이트 + meta.json
src/scene.html        시크 가능한 결정론적 씬. window.__seek(t) 로 상태를 직접 계산
src/render.py         프레임 캡처 → H.264 MP4 인코딩
src/make_reference_poster.py  원본이 없을 때 쓰는 대역 포스터 생성기
build/layers/         분해된 레이어 (재생성 가능)
out/                  결과 MP4
```

**CSS 애니메이션을 쓰지 않는다.** 매 프레임 `__seek(t)` 가 t 로부터 전체 상태를 계산하므로
렌더 속도와 무관하게 타이밍이 정확하고(드랍 프레임 없음), 같은 t 는 항상 같은 프레임을 준다.

프레임 캡처 비용은 사실상 전부 브라우저의 PNG 인코딩이라(1080×1920 한 장에 약 1초),
`--jobs` 로 코어 수만큼 프로세스를 나눠 구간별 세그먼트를 렌더한 뒤 이어 붙인다.
4코어 기준 약 0.23초/프레임, 전체 67초 렌더에 약 8분.

## 다른 포스터에 적용하기

1. 원본을 `assets/poster.png` 에 넣는다 (9:16 이 아니면 가운데 기준으로 커버 크롭된다).
2. `spec/layout.json` 의 `photos` / `sprites` 박스를 실제 좌표에 맞춘다.
   좌표는 0..1 정규화. **키잉 박스는 넉넉한 편이 안전하다** — 딱 맞게 자르면 글자가 잘린다.
   단, 서로 다른 스프라이트의 박스가 겹치면 서로를 이중으로 키잉하니 겹치지 않게 나눈다.
3. `./run.sh --preview` 로 스틸을 확인하고, 어긋나면 2번으로 돌아간다.
4. `./run.sh` 로 전체 렌더.

`keys` 의 색상 임계값(흰 글자 `lum`, 노랑/핑크 `hue`)은 원본 톤에 따라 조정한다.
`extract_layers.py` 는 스프라이트별 `cover` 값을 출력하는데, 0 에 가까우면 키잉이 실패한 것이다.

## 요구 환경

`pip install pillow numpy playwright imageio-ffmpeg` + Chromium.
`imageio-ffmpeg` 가 libx264 가 포함된 ffmpeg 를 함께 가져온다
(Playwright 번들 ffmpeg 는 VP8/WebM 전용이라 MP4 인코딩에 못 쓴다).
